## Positive Security Observations

The codebase has strong security fundamentals:
- **No `shell=True`** in any subprocess call — all use argument lists
- **No `eval()` or `exec()`** on user input; math evaluators use safe AST-walking
- **No unsafe deserialization** — no pickle, all YAML uses `safe_load()`
- **Parameterized SQL everywhere** — all SQLite queries use `?` placeholders
- **Proper path traversal protection** in `file_transfer.py` with `realpath` + boundary checks
- **Security headers** (CSP, X-Frame-Options DENY, X-Content-Type-Options nosniff, Referrer-Policy)
- **Scrypt password hashing** with proper salt, constant-time comparison, rate limiting
- **Atomic file writes** via `tempfile.mkstemp()` + `os.replace()` in identity/config modules
- **Config API masks sensitive keys** before exposing via `/api/config`
- **Good systemd hardening** with MemoryHigh/MemoryMax/TasksMax/CPUQuota

## HIGH Severity

### H1. Scrypt verify_password accepts attacker-controlled cost parameters
**File**: `web_dashboard/auth.py:93-113`
The v2 hash format `scrypt:<salt>:<n>:<r>:<p>:<hash>` reads `n`, `r`, `p` directly from the stored hash string. If an attacker gained write access to `dashboard_secret`, they could craft extreme parameters (e.g., `n=2^30`) causing a denial-of-service by exhausting memory on the Pi during password verification.
**Fix**: Clamp parsed `n`, `r`, `p` to sane upper bounds (e.g., `n <= 2**20`, `r <= 16`, `p <= 16`).

### H2. WebSocket has no Origin header validation
**File**: `web_dashboard/websocket_handler.py:273-286`
The `/ws/metrics` endpoint authenticates via session cookie but performs no `Origin` header check. A malicious page on any domain can open a cross-origin WebSocket (browsers send cookies regardless of Same-Origin). The `_handle_ws_command` function accepts `chirp_capture` and `chirp_set_params` commands, meaning a cross-site attacker could trigger RTL-SDR captures.
**Fix**: Validate the `Origin` header before accepting WebSocket connections.

### H3. Sensor CommandDriver executes arbitrary commands from config
**File**: `builtin_plugins/sensor_framework.py:194-234`
The `CommandDriver` executes whatever command string is in the config via `subprocess.run()`. While `shell=True` is not used and `shlex.split()` provides protection, config file write access = arbitrary command execution as the service user.
**Fix**: Restrict to an allowlist of known sensor-reading binaries, or validate executable paths are in trusted directories.

## MEDIUM Severity

### M1. Auto-generated password logged to journalctl
**File**: `web_dashboard/plugin.py:106-118`
On first run, the generated dashboard password is logged at WARNING level and printed to stdout. The banner even says "Retrieve from journal: journalctl -u reticulumpi | grep password". Anyone with journal read access (adm/systemd-journal groups) can recover the password.
**Fix**: Write password to a file with `0600` permissions instead of the journal, or rotate after first login.

### M2. SSL key file written with permission race window
**File**: `web_dashboard/ssl_utils.py:70-76`
Private key is written with `open(key_path, "wb")` then `os.chmod(key_path, 0o600)` as a separate call. Between the two calls, the file briefly has default umask permissions (often `0o644`).
**Fix**: Use `os.open(key_path, os.O_CREAT | os.O_WRONLY | os.O_TRUNC, 0o600)` + `os.fdopen()` — the same pattern already used correctly in `auth.py:62`.

### M3. `allow_localhost_api` bypasses all authentication
**File**: `web_dashboard/server.py:96-106`
When enabled, all requests from `127.0.0.1`/`::1` skip authentication for ALL endpoints, not just read-only ones. Any local process can modify configuration, restart services, and send messages without credentials.
**Fix**: Limit localhost bypass to GET requests only, or to a specific set of safe endpoints.

### M4. Plugin loader executes arbitrary Python from configured directories
**File**: `plugin_loader.py:30-69`
The loader runs `spec.loader.exec_module()` on any `.py` file in configured `plugin_paths`. No integrity check (signature/hash) on loaded plugins. An attacker who can write a `.py` file to any plugin directory achieves code execution.
**Fix**: Document trust boundary. Consider optional plugin-signing or hash-pinning for production.

### M5. bootstrap.sh `shift` bug
**File**: `scripts/bootstrap.sh:30`
The `shift` at line 30 executes after every `while` loop iteration, including after the `shift` inside `--install-dir` and `--node-name` cases. If those flags are the last argument, the extra `shift` fails with `set -e`, causing the script to exit silently.
**Fix**: Move the `shift` into the default case, or use `shift` only once per argument.

### M6. RateLimiter unbounded memory growth
**File**: `web_dashboard/auth.py:116-154`
The `_attempts` dict is only cleaned per-IP when that IP makes a new request. A distributed brute-force from many IPs grows the dict without bound. On a Pi with limited RAM, this could exhaust memory.
**Fix**: Add periodic sweep in the session GC loop, or use an LRU/TTL cache with max size.

### M7. Logout endpoint doesn't verify caller authentication
**File**: `web_dashboard/api.py:279-293`
The `handle_logout` handler extracts and invalidates a token without checking the caller is authenticated. An attacker who intercepts a token could revoke it without the session cookie.
**Fix**: Add explicit `if not request.get("token")` guard.

## LOW Severity

### L1. `_handle_ws_command` has no message size limit
**File**: `web_dashboard/websocket_handler.py:788-815`
No size limit on incoming WebSocket JSON payloads. aiohttp defaults to 4MB max, which is still large for a Pi.
**Fix**: Set `max_msg_size` on `WebSocketResponse` to ~64KB.

### L2. Session cookie `Secure` flag only set when SSL enabled
**File**: `web_dashboard/api.py:224-234`
When behind a TLS-terminating reverse proxy, the cookie won't be marked Secure since the dashboard itself is HTTP.
**Fix**: Add `force_secure_cookies: true` config option for reverse-proxy deployments.

### L3. `cryptography` dependency floor too low
**File**: `pyproject.toml:37`
`cryptography>=3.0,<5.0` — cryptography 3.x had several CVEs (e.g., CVE-2023-23931 in <39.0.1). Floor should be `>=41.0`.
**Fix**: Raise minimum version.

### L4. Docker rnsd not signal-managed
**File**: `docker/entrypoint.sh:9`
`rnsd &` runs in background without signal forwarding. When Docker sends SIGTERM, rnsd is orphaned and killed by SIGKILL.
**Fix**: Add signal forwarding or use a process supervisor.

### L5. `.claude/` directory should be gitignored
Git status shows `?? .claude/` — should be in `.gitignore` to prevent accidental commits.

### L6. MQTT credentials in config example
**File**: `config/reticulumpi/config.example.yaml:319-320`
The commented example shows `username: meshdev` / `password: large4cats`. Users copying the example may not change them.

## Code Quality & Bugs

### Resource Leaks
- **`meshtastic_gateway.py:1259-1260`** — Two `open()` calls on sysfs without context managers: `int(open(f"{sysfs}/busnum").read().strip())`. Leaks file descriptors, especially during USB reconnect cycles.
- **`auth.py:168-169`** — `sqlite3.connect(db_path)` creates the session DB, then `os.chmod(db_path, 0o600)` restricts it. Between creation and chmod, the DB is world-readable and may contain session tokens.

### Correctness Bugs
- **`mtu.py:51-53`** — `truncate_for_mtu` has O(n²) performance: `while len(truncated.encode("utf-8")) > target: truncated = truncated[:-1]` re-encodes the entire string on every character removal. For CJK text this is ~700 encode operations. The correct pattern (`truncate_bytes`) already exists in the same file at line 24-26.
- **`info_bot.py:89`, `meshtastic_responder.py:122`** — `_safe_eval` Pow guard only limits exponent value, not base. `2**999` produces a 302-digit integer. `2**(-999)` bypasses the `> 1000` guard. Nested `2**(2**30)` also bypasses. Both files have identical copies of this code (duplicate implementation).
- **`app.py:341-361`** — Topo sort marks nodes as `visited` on entry, preventing infinite recursion on cycles but silently producing wrong ordering. If plugin A depends on B and B depends on A, one starts before its dependency with no warning.
- **`remote_client.py:72-74`** — Uses `time.time()` for deadlines. NTP clock correction can extend or shorten timeouts unpredictably. Same pattern in `gps_telemetry.py`, `alert_system.py`, `file_transfer.py`, `websocket_handler.py:409`. Should use `time.monotonic()`.

### Unbounded Collections
- **`mesh_bridge.py:231`** — `self._recent_relays: deque[float] = deque()` has no `maxlen`. A flooding attack appends thousands of entries per second before the next prune pass.
- **`space_tracker.py:119`** — `self._recent: deque[float] = deque()` in `_RateLimiter` has no `maxlen`. Corrupted timestamps that are far in the future prevent pruning.
- **`info_bot.py:535`, `space_tracker.py:252`** — `resp.read()` without size limit on external HTTP responses. A compromised upstream could send unbounded data. Should use `resp.read(max_bytes)`.

### Concurrency
- **`info_bot.py:235`** — `with self._lock:` wraps the entire message handling including external HTTP requests (10s timeout). All other inbound messages queue behind it. Lock should protect only shared state, not the full command dispatch.
- **`event_bus.py:14`** — Module-level `ThreadPoolExecutor(max_workers=4)` created at import, never shut down. 4 daemon threads persist for process lifetime.
- **`websocket_handler.py`** — 12+ module-level globals (`_ws_clients`, `_ws_last_activity`, `_broadcast_task`, etc.) create implicit coupling and make unit testing impossible without monkeypatching.

### Production Assertions
- **`spectrum_scanner.py:404`**, **`adsb_radar.py:292`** — `assert self._rtl_power_path is not None` in `_build_cmd()`. Running Python with `-O` strips asserts, causing obscure `TypeError` instead of informative errors. Should be explicit `if ... raise RuntimeError()`.

### Broad Exception Handling
- **397 `except Exception` clauses** across the codebase. Many silently swallow errors with only `log.debug()` or no logging. Key offenders: `announce_dispatcher.py:178` (announces silently dropped), `event_bus.py:25` (offloaded callbacks), `connectivity_monitor.py:634` (i2pd query failures). This is the project's biggest systemic debugging obstacle.

### Minor
- **`lora_scanner.py:93,100`** — `_lora_snapshot_cache` defined in `validate_config()` then overwritten with same value in `start()`. First assignment is dead code.
- **`lora_chirp_viewer.py:125`** — `_chirp_snapshot_cache` assigned after `super().start()` has already started background threads that might access the attribute.
- **`config.py:135`** — `plugins` property returns shallow copy; inner plugin dicts are shared references. Callers that mutate plugin config modify the original data.

## Frontend Issues

### Security
- **XSS defense is generally good** — the shared `esc()` function is used consistently across nearly all user-data interpolation. However, latent vectors exist:
  - `app.js _di()` helper passes `value` through innerHTML without escaping — not exploitable today but fragile
  - `adsb.js _row()` helper same pattern — callers pass numeric strings, safe for now
  - `ntp.js:43` — `ms.innerHTML = label` where label comes from a dict keyed by server data
- **Login form has no CSRF token** (`login.html`) — server mitigates via `X-Requested-With` header requirement on authenticated calls, but login itself is unprotected
- **WebSocket `onmessage`** — no schema validation on incoming messages; malformed payloads pass to handler functions unchecked
- **WebSocket error handler** — `catch(e) {}` silently swallows all parse/handler errors

### Memory Leaks
- **Zero `removeEventListener` calls** across all 23 JS files
- **12+ permanent global listeners** from messaging panels alone — `window.resize`, `window.scroll`, `document.mousedown` registered per panel instance, never cleaned up
- **Per-row click listeners recreated on every render** in `meshtastic.js`, `meshcore.js`, `adsb.js` — old nodes GC'd via innerHTML replacement but event delegation would be better
- **Permanent window-level listeners** — `mousemove`/`mouseup` in spectrum modules, `resize` in adsb
- **2 unclearable `setInterval` timers** in app.js (2s freshness ticker, 30s data refresh)

### DOM Performance
- **~148 `innerHTML` assignments** across all JS files — nearly all render functions rebuild entire sections on every update, destroying scroll positions, active element state, and selection ranges
- Most impactful in table bodies rebuilt every 30 seconds (mesh, meshtastic, routing, adsb) and conversation/thread lists

### Accessibility (all HIGH severity)
- **Zero ARIA attributes/roles** in the entire 1,050-line index.html
- **22 of 26 form inputs have no `<label>`** — search inputs, text areas, selects all unlabeled
- **No keyboard navigation** — no skip-nav link, no tabindex management, expandable sections use `<div>` with click handlers instead of `<button>` or `<details>`
- **7 `outline: none` declarations** removing focus indicators on login input, search inputs, selects — only 6 `:focus` rules exist and most only change border-color
- **Color contrast** — muted text `#6a7b95` on dark background `#0d1117` is ~3.8:1 ratio, fails WCAG AA (requires 4.5:1)

### Touch/Mobile
- **Spectrum drag-to-zoom** uses only `mousedown`/`mousemove`/`mouseup` — no touch equivalents registered, feature inaccessible on mobile
- **Hover-dependent tooltips** on spectrum/chirp views rely on `mousemove` only
- Responsive breakpoints (480px, 700px, 768px, 1100px) and grid collapse are adequate

### CSS (no significant issues)
- z-index layering (1→9999) is intentional and non-conflicting
- ~25 `!important` uses are all justified (Leaflet overrides, status colors, responsive overrides)
