## Qualification outcome

The recovery-parser correction for the production `sensor_framework.sensors` shape passed its
candidate gates. Subsequent production qualification found a separate RTL-SDR selection ambiguity:
after configuration normalization, a zero-padded value sourced from `device_index` could be
interpreted as a device serial rather than the explicitly configured numeric index. The candidate
failed to launch the required SDR utility when that serial was absent and could not guarantee that
every plugin would bind to the intended physical dongle.

Qualification stopped and stable approval was withheld. The replacement must preserve the
configuration selector type through plugin setup, scheduler arbitration, claim, refresh, and
release, while retaining strict serial matching for values sourced from `device_serial`.

soak evidence; the replacement must rerun those gates using its own exact signed artifacts.
