## Radio recovery and ownership correction

The candidate must keep every direct serial consumer bound to a stable physical identity, reserve
RNS-owned ports before plugins start, and reject duplicate claims across RNode, Meshtastic,
MeshCore, Link Tester, and GPS paths. All reconnects must pass through the generation-fenced owner;
SDK-internal auto-reconnect may not bypass identity revalidation.

Meshtastic health must come from a correlated live control response rather than MQTT activity or
cached metadata. A timed-out private SDK call must not overlap recovery. Soft recovery must either
reopen and verify a new generation or escalate exactly once through the configured identity-bound
USB reset path; reset rate limits and replacement-radio authorization remain durable. Foreign
Meshtastic interfaces must not enter gateway text or data handlers.

The native MQTT path must wait for a successful bounded broker CONNACK and reserve every nonzero
packet ID durably before use. Its legacy node-number-only state rotates once during atomic
enrollment; thereafter the node number and packet-ID state are one fail-closed identity set. No
restart, crash, rejected publish, or uint32 boundary may reuse an encrypted nonce or emit packet ID
zero.

MeshCore error-shaped device-info responses must remain unhealthy in direct and event forms, while
the exact `fw ver` metadata returned by supported older companions remains healthy. Observer local
JWT fallback must sign the exported 64-byte expanded Ed25519 key with the hash-locked MeshCore
runtime dependency. The Link Tester must reconnect after fast and hung I/O failures and accept only
a nonnegative probe count, with exactly zero representing an explicitly unlimited run. Dashboard
states other than `healthy` and `recovered` must remain visibly nonhealthy.
