## Functional scope carried forward

Every direct serial consumer must remain bound to a stable physical identity. RNS-owned ports are
reserved before plugins start, and duplicate claims across RNode, Meshtastic, MeshCore, Link Tester,
GPS, and RTL-SDR paths fail closed. SDK-internal reconnects may not bypass generation-fenced lease
identity validation.

Meshtastic health must come from a correlated live control response rather than MQTT activity or
cached metadata. Timed-out private SDK calls cannot overlap recovery; soft recovery must either
reopen and verify a new generation or escalate exactly once through the configured identity-bound
USB reset. Native MQTT waits for a bounded successful CONNACK and durably reserves every nonzero
packet ID before use, without nonce reuse across restart or exhaustion.

MeshCore must reject error-shaped device information while accepting the exact `fw ver` metadata
from supported older companions. Observer local JWT fallback must sign the exported expanded
Ed25519 key with the hash-locked dependency. Link Tester must recover from fast and hung USB I/O,
and dashboard states other than `healthy` and `recovered` must remain visibly nonhealthy.

LoRa device firmware is not permanently pinned. Qualification records the observed board,
firmware, host-library, stable-path, and USB identity tuple and proves recovery against those exact
devices.

## R32 artifact-only production qualification

R32 is additive and binds terminal R31 as its prepared-but-not-executed predecessor. R18–R31 must
remain byte-for-byte unchanged. R32 uses fresh namespaces and binds the exact v0.3.7 tag, commit,
run attempts, manifest hashes, signatures, and signed-candidate artifact before transfer.

Before any production write, a fresh authenticated preflight must prove the host key, bounded SSH
transport, passwordless `sudo -n`, Ubuntu 24.04 ARM64/Python 3.12 tuple, disk reserve, absence of
active package work, protected-file equality, checksum-only `/etc/dnsmasq.conf` row, systemd and
listener baseline, database integrity, stable radio identities, distinct device claims, and empty
R32 create-once destinations. The established passive unattended-upgrade monitor exception,
package-lock checks, apt-unit checks, and dpkg-update checks remain mandatory.

Deployment must use the exact signed candidate without Git, SCP source checkout, rsync source tree,
or production rebuild. Forward execution retains the established gate order: Gate 00, Gate 71,
baseline capture, recovery-admin installation, external staging, dry-run, transactional apply,
Gate 60 acceptance, Gate 65 functional/network checks, one explicitly authorized reboot, Gate 75,
signed HIL evidence, scheduled soak snapshots, and Gate 85. Gate 60 is invoked only by the apply
controller; rollback remains a contingency path.

Required hardware exercises include correlated RNode exchange, Meshtastic/MeshCore/Link Tester
active probes and forced recovery, physical LoRa unplug/replug, GPS loss and reacquisition, SDR
arbitration, Dashboard and NomadNet access, on-grid/off-grid transitions, and post-reboot identity
continuity. Prior v0.3.6 read-only observations are context only and must be recaptured.
